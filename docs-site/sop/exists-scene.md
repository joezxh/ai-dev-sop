# 已有工程测试与开发自动化 SOP

## 0 文档概述

### 0.1 SOP 目标与用途

本 SOP 面向**已有工程**的全栈开发者与测试工程师，旨在提供一套从「已有工程代码」到「测试自动化」再到「开发自动化」的完整闭环流程。

具体而言，本 SOP 用于解决以下问题：

- **提示词生成效率低**：从已有工程生成测试/开发提示词缺乏标准流程，产出质量参差不齐。
- **测试与开发割裂**：测试发现缺陷后需要人工转交开发，流程断裂效率低下。
- **批量执行能力弱**：缺乏无人值守批量执行机制，无法实现规模化自动化。

本 SOP 以 **scene-template 模板 + /qa-dev Skill + 批量执行机制** 为载体，实现「测试 → 发现 → 开发 → 验证」一体化闭环。

## 1. 从已有工程生成提示词

### 1.1 扫描工程结构与模块

**目标**：全面梳理已有工程的前后端代码结构，识别所有可测试的功能模块。

**前置条件**：
- 已完成工程理解（参考 develop-sop.md §1.1）
- 已安装 superpower / gstack / get-shit-done 等 Skill

**执行步骤**：

1. **扫描后端服务模块**
   - 识别所有微服务及其端口
   - 提取 Controller 中的 API 端点
   - 梳理 Service 层的业务逻辑

2. **扫描前端页面组件**
   - 识别 views 目录下的所有页面
   - 提取 API 调用模块
   - 梳理路由与菜单配置

3. **整理模块清单**

**输出格式**：

```
## 工程模块清单

### 后端服务
| 服务名 | 端口 | 模块数 | 主要功能 |
|-------|------|-------|---------|
| system | 8082 | 24 | 参数配置/字典/日志/监控 |
| harness | 8087 | 12 | AI模块/测试报告 |

### 前端页面
| 页面路径 | API模块 | 权限码 | 对应后端服务 |
|---------|---------|-------|------------|
| /views/system | systemapi | system:* | system:8082 |
| /views/harness | harness | harness:* | harness:8087 |
```

5. 确保开发完成后能够满足原测试场景的所有验证要求
```

## 2. 测试自动化执行

### 2.1 /qa Skill 单模块测试

**目标**：使用 /qa Skill 对单个模块执行浏览器自动化测试。

**适用场景**：已知功能已开发，需要验证功能正确性。

**执行方式**：

1. 从 scene 文件（如 `system-scene.md`）中定位目标模块的测试场景
2. 拷贝该模块的测试场景文字作为 Prompt
3. 将 Prompt 粘贴到 /qa Skill 中执行

**示例**：

```bash
# 假设要测试 SYS-01 参数配置模块

# 步骤1: 打开 scene 文件
docs/scene/system-scene.md

# 步骤2: 定位 SYS-01 模块的测试场景（通常在 5.1 节）
## SYS-01 参数配置

【前置操作】
1. 确认前端(:5173)和后端(:8082)均已启动
2. 使用管理员账号登录

【测试场景 1:参数列表加载】
1. 打开系统管理 → 参数配置页面
2. 验证列表正常加载，显示参数键、参数值、类型、操作列
...

【测试场景 2:新增参数】
1. 点击「新增」按钮
2. 填写参数键、参数值、参数类型
3. 点击「确定」
4. 验证列表刷新，新参数显示
...

# 步骤3: 将上述测试场景文字拷贝到 /qa 执行
/qa
打开系统管理 → 参数配置页面,执行以下测试场景...


**测试流程**：

```
┌─────────────────────────────────────────────────────────────┐
│  1. 打开 scene 文件（如 system-scene.md）                  │
│  2. 定位目标模块的测试场景章节                             │
│  3. 拷贝测试场景文字（Prompt）                            │
│  4. 粘贴到 /qa Skill 执行                                 │
│  5. 浏览器自动化测试执行                                  │
│  6. 生成测试报告                                          │
│  7. 发现问题 → 定位原因 → 提供修复建议                    │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 /qa-dev Skill 二合一增强版

**目标**：一体化执行测试 + 报告 + 自动开发 + 无人值守批量执行。

**核心特性**：

```
┌────────────────────────────────────────────────────────────────────────────┐
│                              /qa-dev                                       │
├────────────────────────────────────────────────────────────────────────────┤
│  Phase 1: 浏览器自动化测试 → Phase 2: 测试报告 → Phase 3: 自动开发       │
└────────────────────────────────────────────────────────────────────────────┘
```

**执行方式**：

从 scene 文件（如 `system-scene.md`）中拷贝目标模块的测试场景文字，将 `/qa-dev` 指令与测试场景一并执行。

**完整流程执行**：

```
/qa-dev --file docs/scene/system-scene.md --module SYS-01
```

或手动方式：

```
# 步骤1: 拷贝 SYS-01 的测试场景
## SYS-01 参数配置

【前置操作】
1. 确认前端(:5173)和后端(:8082)均已启动
2. 使用管理员账号登录

【测试场景 1:参数列表加载】
...

# 步骤2: 执行
/qa-dev --module SYS-01
```

**仅测试不开发**：

```bash
/qa-dev --test-only --file docs/scene/system-scene.md --module SYS-01
```

**仅开发不测试**：

```bash
/qa-dev --dev-only --module SYS-01
```

### 2.3 批量执行与智能流程

#### 2.3.1 批量执行所有模块

```bash
/qa-dev --batch --file docs/scene/system-scene.md
```

#### 2.3.2 分批执行

```bash
# SYS-01 ~ SYS-05
/qa-dev --batch --file docs/scene/system-scene.md --from SYS-01 --to SYS-05

# 仅邮件/短信模块
/qa-dev --batch --file docs/scene/system-scene.md --from SYS-07 --to SYS-17
```

#### 2.3.3 智能流程（三步曲）

```bash
# 1. 先批量测试所有模块
/qa-dev --batch --test-only --file docs/scene/system-scene.md

# 2. 仅开发失败的模块
/qa-dev --batch --dev-only --failed --file docs/scene/system-scene.md

# 3. 重新验证
/qa-dev --batch --file docs/scene/system-scene.md
```

#### 2.3.4 无人值守模式

```bash
# 无人值守批量执行所有模块
/qa-dev --batch --unattended --file docs/scene/system-scene.md

# 无人值守批量执行指定范围
/qa-dev --batch --unattended --file docs/scene/system-scene.md --from SYS-01 --to SYS-10

# 仅测试无人值守
/qa-dev --batch --test-only --unattended --file docs/scene/system-scene.md

# 仅开发失败模块无人值守
/qa-dev --batch --dev-only --failed --unattended --file docs/scene/system-scene.md
```

**无人值守模式特性**：

- 无任何提示、选择或确认请求
- 所有决策自动执行
- 自动处理失败和错误
- 完成后生成完整报告

### 2.4 批量执行流程详解

```
┌────────────────────────────────────────────────────────────────────┐
│  1. 解析 scene 文件 → 提取所有模块定义                             │
│  2. 过滤模块 (--from/--to/--failed)                              │
│  3. 逐个执行: 测试 → 开发 → 验证                                   │
│  4. 生成汇总报告                                                   │
└────────────────────────────────────────────────────────────────────┘
```

## 3. 开发自动化执行

**Skill 文件**：`@.claude/skills/qa-to-dev/SKILL.md`

```
┌─────────────────────────────────────────────────────────────┐
│  1. 执行 /qa 测试                                           │

│  2. 发现功能未开发 → 转换为开发提示词                        │

### 3.2 /qa-dev 开发自动化

**目标**：使用 /qa-dev Skill 实现一体化自动开发。

**完整开发流程**：

```
┌─────────────────────────────────────────────────────────────┐
│  1. 执行 /qa-dev 测试                                       │
│     ↓                                                       │
│  2. 浏览器自动化测试 + 生成报告                             │

│  3. 发现功能未开发 → 自动分析缺失项                        │

**开发自动化执行方式**：

1. 分析缺失的前端组件/API/后端接口
2. 生成完整的开发代码
3. 创建对应的文件
4. 执行回归测试验证

### 3.3 完整闭环验证

**目标**：确保开发完成后通过所有测试场景。

**验证流程**：

1. **代码检查**：确认所有产出物已生成
2. **编译验证**：后端编译通过，前端构建成功
3. **测试回归**：使用 /qa-dev 重新执行测试
4. **报告输出**：生成最终验证报告

**开发任务覆盖**：

| 任务类型 | 产出物 |
|---------|--------|
| 前端页面组件 | Vue 文件（如 `index.vue`、`*FormModal.vue`） |
| 前端 API 封装 | TypeScript 文件（如 `vectorStore.ts`） |
| 后端接口 | Controller、Service、DTO、DO、Mapper |
| 数据库 | 表结构 SQL |
| 权限配置 | 路由 + 菜单 + 权限码注册 |
| 字典数据 | 初始化 SQL |

## 4. 质量保障与成功标准

### 4.1 测试覆盖率

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 页面覆盖率 | 100% | 所有页面都有测试场景 |
| 功能覆盖率 | 100% | 每个按钮/交互都有验证 |

## 5. 最佳实践

### 5.1 测试提示词编写原则

1. **完整性**：遍历每个页面的所有功能
2. **独立性**：每个测试场景可独立执行
3. **可验证**：明确的预期结果与判定标准
4. **可维护**：清晰的模块划分与注释

### 5.2 开发提示词编写原则

1. **结构化**：前端/后端/数据库分离
2. **可执行**：明确的文件路径与代码模板
3. **可验证**：开发完成后可通过测试验证
4. **可复用**：通用逻辑抽离为公共组件

### 5.3 批量执行策略

| 场景 | 推荐策略 |
|------|---------|
| 首次全面测试 | 无人值守批量测试 |
| 回归验证 | 智能流程（测→开→验） |
| 单模块调试 | 单模块测试 |
| 失败模块修复 | 仅开发失败模块 |
