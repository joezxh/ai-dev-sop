# mem0 会话留痕"完全镜像"标准设计（CODEBUDDY.md §2.1 修订）

> **日期**: 2026-09-19
> **状态**: 已批准（用户确认方案① + 800 行安全阀 + 三项落地范围）
> **前置**: CODEBUDDY.md 现行 §2.1（"会话留痕"）在实践中与 CodeBuddy 界面显示差异过大

## 1. 背景与问题

对最近数轮实际入库记录与本会话界面显示的对照勘察，确认五类差距：

| 组件 | 规则要求 | 实际入库情况 | 差距根因 |
|------|---------|-------------|---------|
| 最终回复原文 | "逐字保留，一个字符都不许改" | 界面回复含多个表格/小节，入库版被压缩为几行文字概述 | 缺乏可机械核对的硬校验，压缩无发现机制 |
| Deep Thinking | `> Think:` 插在对应位置 | 每步仅一行要点摘要，界面深度思考块是数百字全文 | 规则未明确"全文还是要点"，执行退化为要点 |
| Tool 调用 | "完整输出" | `> Tool: replace_in_file ×8 → 全部成功` 式合并概括（恰是明令禁止的"×N 概括"） | "关键参数/关键数据"留有压缩口子 |
| Q 部分 | 逐字保留用户完整消息 | 只记键入文本，缺 @文件引用与系统注入上下文 | 未给附加信息的处理办法 |
| 结构标签 | 固定模板 | 标题层级/位置与模板不完全一致 | 模板约束软 |

**根因结论**：现行条款是"描述性"的，缺少可机械核对的结构契约。用户裁定采用**完全镜像**档（非"回复逐字+过程完整"的 60-70% 体积折中方案，也非"仅回复逐字"的最小方案）。

## 2. 决策记录

| 决策点 | 用户裁定 |
|--------|---------|
| 保真级别 | **完全镜像**：最终回复逐字 + Deep Thinking 全文 + 每次工具调用完整参数 JSON 与完整输出 |
| 记录结构 | **方案①：时间线交错 + 编号小节**（拒绝三段分区/JSONL 化） |
| 体积安全阀 | **接受**：单条工具输出 >800 行纯数据性内容可折叠为首尾各 50 行并注明，错误/结论行不得折叠 |
| 落地范围 | 三项：CODEBUDDY.md §2.1 重写 + scripts/templates/mem0-rules.md 同步 + mem0-manual.md §4.2 一句指引 |

## 3. 详细设计

### 3.1 A 部分新模板（时间线交错 + 编号小节）

```markdown
A: 
### Thinking 1（逐字全文）
<该段深度思考全文，逐字保留>

<界面上的过渡叙述行，逐字>

### Tool 1：`工具名`
```json
<完整 arguments，原样 JSON>
```
**输出**：
```text
<完整输出，原样；文件编辑类含 old→new 全文>
```

### Thinking 2（逐字全文）
…

### 最终回复原文（逐字）
<界面最终回复的完整 Markdown，一个字符不改>

### 完成结果
<状态 + 交付物（文件路径） + 验证结论>
```

编排规则：Thinking/叙述行/Tool 严格按**界面实际发生顺序**交错出现；编号（Thinking N / Tool N）从 1 连续递增，供机械自检使用。

### 3.2 关键规则变化（对比现行条款）

1. **Thinking 逐字全文**：废弃 `> Think: 一行摘要`，每段深度思考块整段转录，位置即发生位置。
2. **Tool 完整参数 + 完整输出**：`arguments` 整个 JSON 原样；输出原样（文件编辑类含 old_str/new_str 全文）；失败/被取消的调用同样全量记录（含错误信息）。
3. **比对源改写**：界面显示的思考块/工具卡片/回复与 Agent 上下文一一对应（均为本回合产生），逐字转录的比对源是**本回合上下文**，现行"界面全选复制比对"条款不可执行，改写为"上下文比对"。
4. **Q 部分补全**：用户键入文本逐字之外，界面消息携带的附加信息（@文件引用、系统注入的场景/技能提示）以一行 `> 系统附加上下文：<原文或摘要>` 记录。
5. **增量构建硬性化**：回合中每产生一个界面可见元素（思考块结束/工具调用返回/叙述行发出）即当场把完整内容追加进 A 部分草稿；回合末只允许拼接与自检，禁止任何改写。

### 3.3 体积安全阀（唯一例外）

- 触发条件：单条工具输出超过 **800 行**且属纯数据性内容（大文件读取全文、超长日志）。
- 处理：折叠为**首尾各 50 行** + 明确标注 `…（中间省略 N 行，共 M 行）`。
- 禁止折叠：错误信息、结论行、与任务直接相关的数据行。
- 其余一切内容（含 <800 行的输出、所有 Thinking、最终回复）严格全量。

### 3.4 机械自检（替代现行 6 项软检查）

| # | 检查项 | 判定方式（可机械核对） |
|---|--------|----------------------|
| 1 | Thinking 段数 = 界面深度思考块数 | 编号连续且最大编号 = 实际块数 |
| 2 | Tool 条数 = 本回合实际工具调用次数 | 同上（含失败调用） |
| 3 | 最终回复逐字 | 标题结构（每级 `#` 标题）、表格、代码块语言标注与本回合最终消息完全一致 |
| 4 | 时间线顺序 | Thinking/叙述/Tool 编号顺序 = 实际发生顺序 |
| 5 | Q 逐字 + 系统附加上下文 | 与用户本回合消息一致 |
| 6 | metadata | `created_at` 为提交时刻真实时间（取时间命令已执行）；`turn_seq` = 上一轮 +1 |

任何一项不满足必须补齐后再提交。

### 3.5 不变项

- metadata schema（`type=conversation` / `session_id` 规则 / `agent` / `people` / `role=turn`）不变。
- session_id 生成/复用/跨天重生成规则不变。
- "每轮固定触发，不挑轮次"不变。
- Markdown 为唯一权威载体不变。

## 5. 验收标准

1. 修订后的下一轮会话记录：Thinking 段数与界面深度思考块数相等、Tool 条数与实际调用数相等、最终回复与界面逐字一致（用户在 dashboard 对照验收）。
2. 全量检索：仓库内不再存在"要点式 Think"与"×N 概括 Tool"的规则许可表述。
3. 模板与 CODEBUDDY.md 的 §2.1 内容语义一致（仅占位符差异）。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 单轮记录达数万字符，token 成本上升 | 用户已知情裁定完全镜像；800 行安全阀兜住极端输出；记忆量增长属预期（现行条款已声明） |
| 回合内增量草稿依赖上下文，长回合可能遗漏 | 自检第 1/2 项用计数硬校验兜底；不满足则按上下文回补后提交 |
| 模板/手册/规则文件三处漂移 | 落地范围明确"手册只留指引"，模板与 CODEBUDDY.md 同步改，后续对账以 CODEBUDDY.md 为权威 |
