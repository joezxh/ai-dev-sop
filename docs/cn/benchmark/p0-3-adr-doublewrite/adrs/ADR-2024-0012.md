## 1. 背景与问题陈述

调解平台需要轻量级、可控的鉴权层。Spring Security 学习曲线陡，且与公司 RBAC 模型不完全契合。

## 2. 决策驱动因素

- **业务驱动**：RBAC + 案件隔离 + 临时访问令牌
- **技术驱动**：Spring Security 6.x 配置复杂，过度抽象
- **约束**：3 周内上线 v1

## 3. 备选方案

### 方案 A：Spring Security 6（被拒）
- 优点：生态完整
- 缺点：学习曲线陡、过度抽象、定制 RBAC 复杂
- 成本估算：1 人 / 6 周（学习 + 定制）

### 方案 B：自研 JWT + 拦截器（被选 ✅）
- 优点：实现简单（< 500 行）、可控、与 RBAC 模型对齐
- 缺点：需自研刷新令牌、撤销列表
- 成本估算：1 人 / 2 周

### 方案 C：Sa-Token
- 优点：国内 Java 圈流行、开箱即用
- 缺点：与 Spring Security 兼容、部分功能闭源
- 成本估算：1 人 / 3 周

## 4. 决策

**采纳方案 B · 自研 JWT + 拦截器**。

## 5. 后果与影响

### 5.1 代码影响
- 新增：`adsop.module.system.auth.JwtAuthFilter`
- 新增：`adsop.module.system.auth.TokenStore`（Redis 撤销列表）
- 新增：`adsop.module.system.auth.RbacService`

### 5.2 性能 / 成本影响
- 性能：单请求鉴权开销 < 5ms
- 成本：0 额外费用

### 5.3 风险与缓解
| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| Token 泄露 | 高 | 短 TTL（30min）+ 刷新令牌 + 撤销列表 |
| 自研安全性 | 中 | 季度安全审计 + 渗透测试 |

## 6. 回滚方案

保留 Spring Security 适配层，feature flag 切换。
