## 1. 背景与问题陈述

ChromaDB 单进程无法支撑线上百万级向量规模（2024-Q4 评估）。需要切换到生产级向量库。

## 2. 决策驱动因素

- **业务驱动**：案例库突破 100 万条，ChromaDB 查询 P99 > 800ms
- **技术驱动**：需要 HNSW 索引 + 副本 + 水平扩展
- **约束**：4 周内切换，需保持 API 兼容

## 3. 备选方案

### 方案 A：Qdrant（被选 ✅）
- 优点：Rust 实现性能强、REST+gRPC 双协议、metadata filter 完善
- 缺点：需独立集群（3 节点）
- 成本估算：3 节点 4C8G / 月 ≈ ¥1800

### 方案 B：Milvus
- 优点：生态成熟
- 缺点：架构重、etcd+minio+ pulsar 依赖多
- 成本估算：≥ 6 节点 / 月 ≈ ¥5400

### 方案 C：Weaviate
- 优点：GraphQL 友好
- 缺点：团队不熟悉、文档偏弱
- 成本估算：3 节点 / 月 ≈ ¥2000

## 4. 决策

**采纳方案 A · Qdrant**。

## 5. 后果与影响

### 5.1 代码影响
- 修改：`adsop-module-kms/vectorstore/qdrant_client.py`（替换 chroma_client）
- 保留：`VectorStoreService` 抽象接口不变

### 5.2 性能 / 成本影响
- 性能：查询 P99 降至 120ms（提升 6.7×）
- 成本：月增 ¥1800

### 5.3 风险与缓解
| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 集群 SLO 不达标 | 中 | 与云厂商签 SLA |
| 数据迁移 | 中 | 一次性脚本 + 双写 7 天 |

## 6. 回滚方案

保留 ChromaDB client，feature flag 切回。
